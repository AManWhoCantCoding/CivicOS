# Mô tả module và trạng thái triển khai (AS-IS)

Snapshot: baseline `567380b3c6fea42d359a99d41a8fe4e60134ffa9`, 2026-10-28. Nguồn duy nhất là source code. **Không** khẳng định nghiệm thu hay runtime validated; việc trích dẫn `tests/**` chỉ chứng tỏ bài test được *định nghĩa*, không phải "đã chạy qua lần cuối".

Nhãn trạng thái:
- **Có luồng code** — đầy đủ route → service → persistence trong source.
- **Một phần/giới hạn** — có code nhưng phạm vi bị giới hạn có chủ đích.
- **Mô phỏng** — mock/fixture không mạng, không phải tích hợp thật (áp dụng cho **camera** và **CSDL quốc gia**).
- **Biên dịch vụ được cấu hình (chưa kiểm chứng runtime)** — ví dụ TileServer GL provider bản đồ: source cấu hình mặc định tới `http://localhost:8080` nhưng snapshot không chứng minh dịch vụ đã chạy.
- **Chưa đủ bằng chứng** — hiện diện trong code nhưng chưa được kiểm chứng runtime trong snapshot này.

## Ranh giới quyền và dữ liệu cần ghi nhớ

- **Điều hướng ≠ authorization:** sidebar/menu chỉ lọc hiển thị theo role/task/organization scope; việc chặn thao tác thực tế do server enforce qua access check từng module (ví dụ `assertLandActor`, `requireLandReviewAccess` tại `src/modules/land/sync-service.ts:96-114`).
- Mọi tích hợp **camera** và **CSDL quốc gia** đều là mock/fixture, không gọi mạng; biến env `LAND_MOCK_SYNC_OUTCOME` chọn kết quả mock success/failure (`sync-service.ts:65-71`). Riêng **provider bản đồ** (TileServer GL mặc định `http://localhost:8080`, `official:false` — `src/modules/platform/map/index.ts`) là biên dịch vụ thật được cấu hình, nhưng snapshot chưa kiểm chứng nó đang chạy.
- Mobile có **offline queue** + đồng bộ qua `POST /api/sync`; chỉ áp dụng cho nhóm lệnh giới hạn, đồng nghĩa mobile **không có web-write parity** — chi tiết tại [screen-flows.md](screen-flows.md) và [interfaces-apis.md](interfaces-apis.md).
- Audit được ghi thủ công trong các sự kiện nghiệp vụ (ví dụ `auditLandEvent` tại `sync-service.ts:248-269`), không phụ thuộc auto-trigger từ DB.

## Những gì chưa kiểm chứng runtime

Toàn bộ bảng trên chỉ nói về **code hiện có**, không phải trạng thái pass/fail của suite hay runtime. Người đọc quan tâm đến ready-for-production cần:
1. chạy lại database-backed checks như `npm test`, `node scripts/e2e/run-vitest-db.mjs`, `npm run typecheck`, `npm run build`, `npm run mobile:*` (xem khối `verify` trong `package.json`) để làm mới bằng chứng;
2. đối chiếu theo `Requirement.md` (Epic PS-E1) và `docs/demo-script.md`, `docs/runbooks/` — các tài liệu này vẫn giữ nguyên, **không** do snapshot này thay thế;
3. **không** kết luận "PS-E1 hoàn thành" từ một snapshot code đơn thuần — từng module có thể sở hữu code nhưng chưa được chạy e2e cùng nhau.
