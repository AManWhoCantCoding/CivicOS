# Reusable engineering lessons

- **Native E2E/Prisma setup** — **Symptom:** query-engine rename `EPERM`, port/connection readiness races, or destructive E2E runs against the wrong database. **Root cause:** unowned locks, one-shot liveness checks, and unsafe database defaults. **Prevention/handling:** use PID/token-owned locks, liveness checks, stable consecutive health probes, ownership-scoped cleanup, a safe no-drop default, and explicit destructive opt-in. **Verification:** exercise startup, readiness, cleanup, and database-selection paths under retries and competing processes.
- **Transactional validation** — **Symptom:** after a failed command, the next error reports the first missing template item instead of the later invalid input. **Root cause:** command validation and checklist-response writes are transactional, so partial responses roll back. **Prevention/handling:** preserve rollback semantics and validate server behavior for blank and whitespace input. **Verification:** assert both the validation error and rolled-back checklist state, not only the UI result.
- **Aggregate version synchronization** — **Symptom:** a following Approval/online command fails with a stale-base conflict after the preceding command increments the version. **Root cause:** the UI issues the next command before refreshing or consuming the returned aggregate version. **Prevention/handling:** await refresh or use the returned version before issuing the next command. **Verification:** run multi-command desktop and mobile flows and assert each command uses the latest version.
- **Native Windows env propagation** — **Symptom:** DB-gated Vitest silently skips under bash/WSL when `RUN_DB_TESTS=1` is prefixed/exported. **Root cause:** the Windows `node.exe` process does not inherit that WSL shell environment. **Prevention/handling:** use native PowerShell `$env:RUN_DB_TESTS='1'; npx.cmd ...` and verify skip count is zero. **Verification:** compare final test summary.
- **Schema/migration test ordering** — **Symptom:** DB tests fail with missing column immediately after adding a migration. **Root cause:** migration file exists but has not been deployed to the active test DB. **Prevention/handling:** run `prisma migrate deploy`/status before DB tests without reset/drop. **Verification:** confirm migration count/status and rerun the failing DB test.
- **Outbox retry backoff** — **Symptom:** a failed notification consumer spins until a workflow times out and retry attempts are not observable. **Root cause:** a drain loop treated failed work as immediately available despite future `availableAt`, and overlapping worker ticks raced over the same queue. **Prevention/handling:** honor retry backoff, serialize worker ticks, and expose deterministic retry progression without busy loops. **Verification:** assert attempts, delayed reprocessing, exactly-once processing, and dependent SLA flows across repeated runs.
- **Transactional evidence binding** — **Symptom:** an Evidence row or file can remain after attaching it to the domain resource fails. **Root cause:** upload persistence and resource projection/audit updates were separate operations. **Prevention/handling:** use one transaction-aware application path with storage cleanup on rollback and verify foreign-resource/actor scope. **Verification:** force attachment failure and assert no orphan DB evidence, audit, or projection remains.
