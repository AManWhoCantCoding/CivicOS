# Reusable engineering lessons

- **Native E2E/Prisma setup** — **Symptom:** query-engine rename `EPERM`, port/connection readiness races, or destructive E2E runs against the wrong database. **Root cause:** unowned locks, one-shot liveness checks, and unsafe database defaults. **Prevention/handling:** use PID/token-owned locks, liveness checks, stable consecutive health probes, ownership-scoped cleanup, a safe no-drop default, and explicit destructive opt-in. **Verification:** exercise startup, readiness, cleanup, and database-selection paths under retries and competing processes.
- **Transactional validation** — **Symptom:** after a failed command, the next error reports the first missing template item instead of the later invalid input. **Root cause:** command validation and checklist-response writes are transactional, so partial responses roll back. **Prevention/handling:** preserve rollback semantics and validate server behavior for blank and whitespace input. **Verification:** assert both the validation error and rolled-back checklist state, not only the UI result.
- **Aggregate version synchronization** — **Symptom:** a following Approval/online command fails with a stale-base conflict after the preceding command increments the version. **Root cause:** the UI issues the next command before refreshing or consuming the returned aggregate version. **Prevention/handling:** await refresh or use the returned version before issuing the next command. **Verification:** run multi-command desktop and mobile flows and assert each command uses the latest version.
- **Native Windows env propagation** — **Symptom:** DB-gated Vitest silently skips under bash/WSL when `RUN_DB_TESTS=1` is prefixed/exported, PowerShell targets a wrong database name such as `=public`, or WSL reports `docker`/Docker Desktop unavailable while native Windows `docker.exe info` and PostgreSQL still work. **Root cause:** the Windows `node.exe` process does not inherit that WSL shell environment, native `$variable?schema`/nested-quote expansion misparses connection URLs, and WSL/Windows have separate PATH/CLI/daemon integration for Docker/database runtimes. **Prevention/handling:** use native PowerShell `$env:RUN_DB_TESTS='1'; npx.cmd ...`, build URLs by explicit concatenation, verify skip count is zero, verify the exact DB name before/after cleanup, and run Docker, compose, Node/npm, PostgreSQL checks and test commands through native Windows PowerShell/`powershell.exe`, never inferring infrastructure failure from WSL-only commands. **Verification:** compare final test summary, assert connected/database-created names, and require native `docker.exe info`, `docker.exe compose ps`, and a native database connectivity query to all pass.
- **Schema/migration test ordering** — **Symptom:** DB tests fail with missing column immediately after adding a migration, or a fresh DB shows order-dependent missing-fixture failures mistaken for product regressions. **Root cause:** migration file exists but has not been deployed to the active test DB, or the fresh DB lacks a deterministic reference/session seed boundary before the full suite. **Prevention/handling:** run `prisma migrate deploy`/status before DB tests without reset/drop, establish the seed boundary first on a clean disposable DB, and verify the shared DB is unchanged. **Verification:** confirm migration count/status, seed boundary, and rerun the failing DB test.
- **Outbox retry backoff** — **Symptom:** a failed notification consumer spins until a workflow times out and retry attempts are not observable. **Root cause:** a drain loop treated failed work as immediately available despite future `availableAt`, and overlapping worker ticks raced over the same queue. **Prevention/handling:** honor retry backoff, serialize worker ticks, and expose deterministic retry progression without busy loops. **Verification:** assert attempts, delayed reprocessing, exactly-once processing, and dependent SLA flows across repeated runs.
- **Transactional evidence binding** — **Symptom:** an Evidence row or file can remain after attaching it to the domain resource fails. **Root cause:** upload persistence and resource projection/audit updates were separate operations. **Prevention/handling:** use one transaction-aware application path with storage cleanup on rollback and verify foreign-resource/actor scope. **Verification:** force attachment failure and assert no orphan DB evidence, audit, or projection remains.
- **Projection/read consistency** — **Symptom:** an aggregate detail endpoint shows an older status while its timeline already contains a newer domain event. **Root cause:** the response mixed an eventually consistent projection with strongly consistent aggregate events. **Prevention/handling:** choose one authoritative consistency boundary for detail responses (or compare aggregate versions) and keep status/timeline derived from the same version. **Verification:** complete approval/resolve/close flows with worker lag and assert status version equals the latest timeline event.
- **Browser fixture isolation** — **Symptom:** a login helper observes zero new session POSTs or a retry reports the Next app exited after a prior E2E failure. **Root cause:** stale session cookies/context state and incomplete app-process teardown leak across tests. **Prevention/handling:** clear session state before every asserted login, wait on the exact response caused by the submit, and tear down partial app startup/process groups on every failure. **Verification:** repeat full desktop/mobile suites and assert each login request and clean readiness.
- **Offline queue convergence** — **Symptom:** offline commands remain pending during a browser sync poll even though the browser is online, or seeded offline fixtures mutate on mount. **Root cause:** one-shot online-mount sync races, stale leases, multiple tabs performing unsynchronized localStorage read-modify-write updates, or mount auto-sync racing fixture seeding. **Prevention/handling:** make online sync idempotent and convergent, reclaim stale leases, reconcile authoritative server state, serialize per-item updates, force initial browser offline before mounting seeded fixtures then restore native online state before transition tests, and drive sync through an explicit UI action without weakening terminal-status assertions. **Verification:** repeat multi-command offline desktop/mobile flows, assert seeded queue is unchanged until the explicit transition, and require every expected item to reach truthful synced/rejected state.
- **Browser form custom validation** — **Symptom:** a form with app-owned accessible errors never shows the custom error on empty submit. **Root cause:** native `required` validation blocks the React submit handler before app code runs. **Prevention/handling:** use `noValidate` when the app owns validation while preserving semantic labels/`required`, and surface errors in an accessible container. **Verification:** submit empty/invalid input and assert the custom role alert/status message.
- **Shared-service E2E contention** — **Symptom:** unrelated navigation/readiness flakes appear only in the full E2E run. **Root cause:** concurrent Playwright workers saturate a shared Next dev server/database. **Prevention/handling:** serialize the shared-service suite or establish deterministic readiness, and never hide failures with sleeps/retries. **Verification:** rerun the serialized suite and assert readiness probes plus previously flaky navigations pass deterministically.
