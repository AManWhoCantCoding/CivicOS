# Reusable engineering lessons

- **Sensitive reveal needs explicit role and tenant gates** — **Symptom:** a shared `read_sensitive` policy seam can reveal protected intake identity to a role or organization that should only have ordinary access. **Root cause:** capability evaluation was treated as sufficient without enforcing the business role and exact resource `OrganizationUnit` boundary at the aggregate read seam. **Prevention/handling:** fail closed unless the required role, exact organization scope, and capability all hold; keep masking as the default. **Verification:** test each missing role, cross-unit actor, missing unit, and capability denial.

- **Verified-path reads — additional variant** — **Symptom:** a read is rejected immediately after an accidental null byte is included in a Windows path argument. **Root cause:** the path string was not preserved safely by the tool argument. **Prevention/handling:** verify the parent and retry with a slash-separated repository path; do not treat the tool error as a repository failure. **Verification:** the retried read returns the expected file before repository review continues.

- **Native E2E/Prisma setup** — **Symptom:** query-engine rename `EPERM`, port/connection readiness races, a Prisma NAPI engine panic during concurrent teardown, or destructive E2E runs against the wrong database. **Root cause:** unowned locks, one-shot liveness checks, unsafe database defaults, or overlapping Prisma engine cleanup. **Prevention/handling:** use PID/token-owned locks, liveness checks, stable consecutive health probes, ownership-scoped cleanup, a safe no-drop default, explicit destructive opt-in, and rerun the affected DB command in isolation after an engine panic. **Verification:** exercise startup, readiness, cleanup, and database-selection paths under retries and competing processes; require a clean isolated rerun.
- **Transactional validation** — **Symptom:** after a failed command, the next error reports the first missing template item instead of the later invalid input. **Root cause:** command validation and checklist-response writes are transactional, so partial responses roll back. **Prevention/handling:** preserve rollback semantics and validate server behavior for blank and whitespace input. **Verification:** assert both the validation error and rolled-back checklist state, not only the UI result.
- **Aggregate version synchronization** — **Symptom:** a following Approval/online command fails with a stale-base conflict after the preceding command increments the version. **Root cause:** the UI issues the next command before refreshing or consuming the returned aggregate version. **Prevention/handling:** await refresh or use the returned version before issuing the next command. **Verification:** run multi-command desktop and mobile flows and assert each command uses the latest version.
- **Persistence version vs. event-stream version** — **Symptom:** a later command fails with `AGGREGATE_VERSION_CONFLICT` after an earlier workflow-only update increments the aggregate row version without emitting a domain event. **Root cause:** the later event reused the persistence version even though `appendEvent` sequences against the latest event-stream version. **Prevention/handling:** preserve the existing event contract and calculate each new event version from `getAggregateVersion(...) + 1` when row metadata can advance without an event. **Verification:** exercise the workflow-only update followed by its next event and assert contiguous event versions plus successful transaction/idempotent replay.
- **Native Windows env propagation** — **Symptom:** DB-gated Vitest silently skips under bash/WSL when `RUN_DB_TESTS=1` is prefixed/exported, PowerShell targets a wrong database name such as `=public` (including disposable replay setup), WSL reports `docker`/Docker Desktop unavailable while native Windows `docker.exe info` and PostgreSQL still work, or `powershell.exe -Command "..."` fails with `:RUN_DB_TESTS=1 ... not recognized`. **Root cause:** the Windows `node.exe` process does not inherit that WSL shell environment, native `$variable?schema`/nested-quote expansion misparses connection URLs, WSL/Windows have separate PATH/CLI/daemon integration for Docker/database runtimes, and bash expands `$env` inside double quotes before PowerShell sees it. **Prevention/handling:** use native PowerShell `$env:RUN_DB_TESTS='1'; npx.cmd ...`, build URLs by explicit concatenation, verify skip count is zero, verify the exact DB name before/after cleanup, and run Docker, compose, Node/npm, PostgreSQL checks and test commands through native Windows PowerShell/`powershell.exe`, never inferring infrastructure failure from WSL-only commands; when invoking `powershell.exe` from bash, single-quote the whole `-Command` argument so `$env:` reaches PowerShell literally. **Verification:** compare final test summary, assert connected/database-created names, and require native `docker.exe info`, `docker.exe compose ps`, and a native database connectivity query to all pass.
- **Schema/migration test ordering** — **Symptom:** DB tests fail with missing column immediately after adding a migration, or a fresh DB shows order-dependent missing-fixture failures mistaken for product regressions. **Root cause:** migration file exists but has not been deployed to the active test DB, or the fresh DB lacks a deterministic reference/session seed boundary before the full suite. **Prevention/handling:** run `prisma migrate deploy`/status before DB tests without reset/drop, establish the seed boundary first on a clean disposable DB, and verify the shared DB is unchanged. **Verification:** confirm migration count/status, seed boundary, and rerun the failing DB test.
- **Outbox retry backoff** — **Symptom:** a failed notification consumer spins until a workflow times out and retry attempts are not observable. **Root cause:** a drain loop treated failed work as immediately available despite future `availableAt`, and overlapping worker ticks raced over the same queue. **Prevention/handling:** honor retry backoff, serialize worker ticks, and expose deterministic retry progression without busy loops. **Verification:** assert attempts, delayed reprocessing, exactly-once processing, and dependent SLA flows across repeated runs.
- **Transactional evidence binding** — **Symptom:** an Evidence row or file can remain after attaching it to the domain resource fails. **Root cause:** upload persistence and resource projection/audit updates were separate operations. **Prevention/handling:** use one transaction-aware application path with storage cleanup on rollback and verify foreign-resource/actor scope. **Verification:** force attachment failure and assert no orphan DB evidence, audit, or projection remains.
- **Projection/read consistency** — **Symptom:** an aggregate detail endpoint shows an older status while its timeline already contains a newer domain event. **Root cause:** the response mixed an eventually consistent projection with strongly consistent aggregate events. **Prevention/handling:** choose one authoritative consistency boundary for detail responses (or compare aggregate versions) and keep status/timeline derived from the same version. **Verification:** complete approval/resolve/close flows with worker lag and assert status version equals the latest timeline event.
- **Browser fixture isolation** — **Symptom:** a login helper observes zero new session POSTs or a retry reports the Next app exited after a prior E2E failure. **Root cause:** stale session cookies/context state and incomplete app-process teardown leak across tests. **Prevention/handling:** clear session state before every asserted login, wait on the exact response caused by the submit, and tear down partial app startup/process groups on every failure. **Verification:** repeat full desktop/mobile suites and assert each login request and clean readiness.
- **Offline queue convergence** — **Symptom:** offline commands remain pending during a browser sync poll even though the browser is online, or seeded offline fixtures mutate on mount. **Root cause:** one-shot online-mount sync races, stale leases, multiple tabs performing unsynchronized localStorage read-modify-write updates, or mount auto-sync racing fixture seeding. **Prevention/handling:** make online sync idempotent and convergent, reclaim stale leases, reconcile authoritative server state, serialize per-item updates, force initial browser offline before mounting seeded fixtures then restore native online state before transition tests, and drive sync through an explicit UI action without weakening terminal-status assertions. **Verification:** repeat multi-command offline desktop/mobile flows, assert seeded queue is unchanged until the explicit transition, and require every expected item to reach truthful synced/rejected state.
- **Browser form custom validation** — **Symptom:** a form with app-owned accessible errors never shows the custom error on empty submit. **Root cause:** native `required` validation blocks the React submit handler before app code runs. **Prevention/handling:** use `noValidate` when the app owns validation while preserving semantic labels/`required`, and surface errors in an accessible container. **Verification:** submit empty/invalid input and assert the custom role alert/status message.
- **Shared-service E2E contention** — **Symptom:** unrelated navigation/readiness flakes appear only in the full E2E run; after serializing and reducing to one browser project, unrelated domain setup calls can still return `500` while the targeted module flow remains green. **Root cause:** the full suite shares a mutable Next/Prisma environment and couples the target flow to pre-existing fixtures/read-model or intake state. **Prevention/handling:** serialize the shared-service suite, establish deterministic readiness and seed state, and classify failures by failing spec before changing the current module; never hide failures with sleeps/retries or claim a targeted pass as a full-suite pass. **Verification:** rerun the serialized suite, assert readiness probes, run the target module's focused browser flow, and record unrelated failures separately.
- **Persisted-authority seeding in DB tests** — **Symptom:** every grant/assignment path fails with a compatibility error (e.g. `INCOMPATIBLE_TASK`) even though the in-memory caller object carries the right roles, cascading into multiple integration failures. **Root cause:** enforcement reads authority from the persisted store (Role/UserRole rows), not from the caller's in-memory role list, while the test seeded User rows without any role rows. **Prevention/handling:** seed the persisted authority rows (upsert catalog Role, create UserRole per test user, reusing the pattern from sibling DB tests) in `beforeAll`; rely on user-delete cascade for cleanup. **Verification:** rerun the DB-gated suite and assert zero skips plus grant paths succeeding for compatible roles and rejecting for incompatible ones.
- **Privilege-tightening sweep over sibling tests** — **Symptom:** after removing a privileged bypass from a policy evaluator, an unrelated sibling DB test fails asserting the old privileged behavior (e.g. commander `mutate` without assignment). **Root cause:** the old bypass was encoded as expected behavior in tests outside the changed file. **Prevention/handling:** when tightening a policy, grep every DB/contract test asserting the privileged actor's access and update each to the new rule (assignment-free scope vs. assignment-required actions), granting the privileged actor explicit assignments in integration fixtures where module flows require mutation. **Verification:** rerun the full affected suites with DB enabled and assert zero failures, not just the focused file. For a role gate that separates command approval from fieldwork, use a field-officer fixture with a persisted active task assignment and keep a pure commander fixture for the denial regression.
- **Exact public-surface export test** — **Symptom:** adding a legitimate public helper breaks an unrelated test asserting the exact `Object.keys` list of a module entry point. **Root cause:** the allow-list snapshot was written before the new helper and treats any export delta as a regression. **Prevention/handling:** when extending a guarded public surface, update the expected export list in the same change while keeping the no-database-internals assertion intact. **Verification:** rerun the entry-point test plus the full affected suite and confirm the internals guard still passes.
- **Prisma migration-table column assumption** — **Symptom:** a migration-applied check fails with `column "success" does not exist` (`42703`) on `_prisma_migrations`. **Root cause:** the test assumed a `success` column that this Prisma version does not create; applied state is represented by non-null `finished_at` plus `applied_steps_count`. **Prevention/handling:** inspect the real table definition (`\d _prisma_migrations` or equivalent) before asserting on its columns; assert applied via `finished_at IS NOT NULL` and `applied_steps_count > 0`. **Verification:** rerun the migration-status test and confirm the applied assertion passes without touching migration history.
- **Scoped E2E text locators** — **Symptom:** a Playwright text assertion fails with strict-mode violation resolving to multiple elements (e.g. an email shown both in the session header and in a data table), or a `.first()` assertion silently binds to newly added shared chrome (e.g. a breadcrumb section label) instead of the intended page content. **Root cause:** the locator matched repeated identity copy outside the intended region, or new chrome introduced an exact-text node earlier in DOM order than the target. **Prevention/handling:** scope content assertions to the target region (`getByRole('table')` + `toContainText`, row/cell locators) instead of page-wide `getByText`; when ADDING shared chrome, grep existing specs for exact-text matches of every new visible string first and prefer labels that cannot exact-collide (e.g. qualified section crumbs). **Verification:** rerun the spec on all projects and assert each locator resolves to exactly the intended element.
- **Required-artifact permission preflight** — **Symptom:** implementation and tests pass, but a ticket cannot reach its required final state because a required ADR/document is rejected by the agent harness permission policy. **Root cause:** the allowed-file list was checked for scope but write permission for documentation was not verified before execution. **Prevention/handling:** preflight every required artifact path and, when permission is denied, do not bypass the guardrail or claim completion; record the exact denial, preserve completed code evidence, and close/retry the ticket only after the documented path is writable. **Verification:** confirm the required file exists on disk and is included in the reviewer’s acceptance check before marking the ticket done.
- **Nested-scroll action interception on mobile E2E** — **Symptom:** a Playwright check/click inside a scrollable picker list times out with another element intercepting pointer events, systematically on the mobile project while desktop passes. **Root cause:** programmatic scroll-into-view settles the control under a sibling or scroll-container box in narrow viewports, so hit-testing never succeeds no matter how long it retries. **Prevention/handling:** keep the behavioral assertion on the server-observable outcome (success message plus follow-up role steps proving the mutation), and use forced actions only for the mechanical toggle/click without dropping the outcome assertions. **Verification:** rerun the spec on all projects and require the full flow green on each.
- **Assignment compatibility is not action authorization** — **Symptom:** a privileged role executes a subordinate-only action while holding an active compatible Assignment for the resource. **Root cause:** the grant-time task/role compatibility check passed, and the command relied solely on the Assignment match without re-checking the actor role at execution time. **Prevention/handling:** enforce the actor-role gate at the command boundary in the owning module and treat grant-time compatibility as hygiene only, never as execution permission. **Verification:** regression test with the privileged actor holding an active Assignment asserting rejection plus zero new domain events and zero mutation audits.
- **DB-gated verification requires preflight readiness** — **Symptom:** a DB-enabled test command starts but fails in `beforeAll`/`afterAll` with Prisma unable to reach `localhost:5432`, leaving the intended regression tests skipped. **Root cause:** the PostgreSQL service was not ready before the test process began. **Prevention/handling:** stop without starting Docker or substituting another database; have the infrastructure owner prepare and verify the approved database, then rerun the exact DB-gated command. **Verification:** require the suite to execute with zero skipped tests and a successful database connection before interpreting regression results. **Biến thể:** Docker daemon hoặc tileserver healthy không chứng minh PostgreSQL đang chạy; kiểm tra service/container `postgres`, port `5432` và kết nối thực tế trước khi phân loại lỗi test.
- **E2E actor-fixture alignment** — **Symptom:** a field-officer lifecycle receives `403` or the checklist controls disappear even though the inspection UI loads. **Root cause:** the browser fixture either creates the schedule without an active assignment or logs in a commander before exercising fieldwork-only controls. **Prevention/handling:** select the intended assignee in UI-created schedules and retain the field-officer session for fieldwork/offline assertions; keep server authorization unchanged. **Verification:** assert the assignment and role-specific controls through desktop and mobile lifecycle tests.
- **E2E projection worker startup** — **Symptom:** a mutation succeeds through the authoritative API but polling never observes the corresponding read-model entry. **Root cause:** the browser server was started without the outbox/projection worker, so domain events remained pending even though the write model was correct. **Prevention/handling:** start the application and worker as separate Playwright-managed processes using the inherited database environment; keep read-model assertions intact and avoid seed/reset/drop commands. **Verification:** create each resource, poll its read model, and require the projection entry before checking the UI.
- **Assignment-management boundary in scheduling** — **Symptom:** a non-commander can schedule an inspection but an assigned schedule fails through a generic authorization error. **Root cause:** scheduling and assignment creation were combined even though assignment management is commander-only. **Prevention/handling:** make the boundary explicit: office roles may create unassigned schedules, while commanders create fieldwork assignments separately; expose a distinct denial and test both paths. **Verification:** assert no assignment is created by the office path and that commander assignment plus field actor access still work.
- **Authorization-aware E2E fixtures** — **Symptom:** an existing end-to-end helper receives `403` after role permissions are tightened. **Root cause:** the fixture performs a mutation with a role that is intentionally read-only for that workflow. **Prevention/handling:** keep registry setup in the command role, then authenticate as the field role before creating observations or exercising fieldwork. **Verification:** rerun every desktop and mobile project and assert the full workflow, not just page rendering.
- **Action-specific assignment lookup** — **Symptom:** an authorized UI hides a valid action or waits until timeout when a resource has multiple active assignments. **Root cause:** an unordered `findFirst` selected a different task assignment than the action being rendered. **Prevention/handling:** query the assignment for each action-specific task explicitly and derive UI permissions from role plus that resource assignment. **Verification:** exercise the same resource with report and verification assignments and assert the intended controls are visible only for the matching session.
- **Session restoration in browser authorization checks** — **Symptom:** a later API assertion returns the wrong status after an added UI permission assertion. **Root cause:** the test changed the logged-in actor and continued without restoring the actor required by the next request. **Prevention/handling:** make every actor switch explicit and restore the session immediately before dependent API checks. **Verification:** assert the actor-specific endpoint status and run all browser projects.
- **Tool path preflight** — **Symptom:** a file read fails immediately with a malformed or assumed path before execution begins. **Root cause:** an invalid path string was supplied, or a nested ticket/plan/review path was guessed instead of verified; a root-directory probe or malformed path can also occur while resolving the workspace. **Prevention/handling:** use the verified workspace root and exact path before issuing reads or edits; enumerate the parent directory when the path is uncertain, including when a ticket is stored under an `issues/` subdirectory or its evidence plan/review is stored under a ticket-specific directory. **Verification:** confirm the target exists with a directory/file lookup and rerun the intended read; if a malformed path is issued, record the tooling incident rather than treating it as a repository failure. **Biến thể:** nếu candidate ở root không tồn tại, dừng đoán tên file và lần lượt enumerate `.scratch`, feature directory rồi `issues/` trước khi đọc lại; không dùng lại candidate path đã thất bại trong cùng vòng review. **Biến thể module:** không đoán tên file con của một module; enumerate/glob đúng thư mục rồi chỉ đọc path đã xác nhận. **Biến thể plan:** không đoán `plan.md` ở root; enumerate evidence directory của ticket rồi đọc file kế hoạch tại đường dẫn đã xác nhận. **Biến thể standards:** nếu tài liệu chuẩn được yêu cầu không tồn tại tại đường dẫn đã xác nhận, enumerate thư mục tài liệu một lần, ghi nhận thiếu tài liệu thay vì tiếp tục đoán tên, và nêu rõ giới hạn đối chiếu trong báo cáo.
  - **Biến thể artifact review:** nếu file direction review được tham chiếu nhưng không tồn tại, enumerate thư mục evidence của ticket và dùng đúng artifact đã xác nhận; ghi nhận đây là sự cố path, không phải thiếu direction evidence.
- **Git index refresh noise** — **Symptom:** `git update-index --refresh` reports many unrelated files as needing update while the target content diff is empty. **Root cause:** working-tree stat metadata is stale or differs from the index without a content change. **Prevention/handling:** inspect the target’s content diff and status separately; do not rewrite unrelated files. **Verification:** require an empty target diff and `git diff --check` before reporting the target status.
- **Async-content-aware client effects** — **Symptom:** role-filtered navigation stays in loading long after its fast endpoints respond, or a dialog/drawer focus effect never lands on the first link. **Root cause:** one effect gates visibility on the slowest fetch at once, or an entry-focus effect runs a single time before the async list renders. **Prevention/handling:** render from the fastest authoritative signal (session) first and refine when scoped data arrives, skip scoped fetches no visible feature needs, fail closed on fetch errors, and re-run entry-focus when async content arrives guarded to never steal focus already inside the dialog. **Verification:** assert nav links appear promptly and dialog focus lands on slow loads across desktop and mobile projects.
- **Cold-dev heavy-page locator timeouts** — **Symptom:** a first-visit browser assertion times out at the default 5s on a heavy page while an isolated rerun or manual probe resolves seconds later, with each API individually fast. **Root cause:** cold route/chunk compilation plus slow pre-existing endpoints on the same page saturate the dev server, so the asserted fetch queues behind them. **Prevention/handling:** keep locators exact and extend the timeout only on the heavy page’s readiness assertions; keep the tree static during timing probes because creating/deleting project files triggers rebuilds that invalidate measurements. **Verification:** rerun the full spec on all projects green without weakening any locator.
- **Same-basename backup before destructive checkout** — **Symptom:** after a `cp` backup plus `git checkout --`, gated changes are unrecoverable because several source files share one basename and later copies were refused. **Root cause:** copying multiple same-named files into one flat directory silently keeps only the first. **Prevention/handling:** back up with preserved relative paths (or one uniquely named copy per file) and list/verify backup completeness before any destructive restore. **Verification:** require the backup file count to equal the target count and `git diff --stat` to show the expected delta only after restore.
- **Validated display target is not a bound connection** — **Symptom:** a seed/reset script prints and validates the correct demo database yet writes/truncates a different database. **Root cause:** the guard checked a resolved URL string while the ORM singleton had already been constructed at import time from the ambient connection env, so validation never touched the actual connection. **Prevention/handling:** keep the guard module dependency-free, resolve + validate the target first, apply the validated target to the connection env, and only then dynamic-import any module that opens a connection; never static-import the client in the guarded entry point. **Verification:** regression test with the ambient connection pointing at a non-demo database asserting the effective connection equals the validated demo target, plus a guard refusal test for the non-demo URL.
- **Minimal structural env-param types in scripts** — **Symptom:** typecheck rejects minimal test env objects passed to script helpers typed as the global env type, or rejects the real `process.env` with no-properties-in-common once the helper type is narrowed to only optional keys. **Root cause:** the helpers coupled their input to ambient global declarations, and a follow-up type with only optional keys is a weak type with no overlap. **Prevention/handling:** type script env inputs as a minimal structural type carrying a matching index signature (`[key: string]: string | undefined`) plus only the optional keys used; keep the real `process.env` assignable as the default without `as` casts. **Verification:** typecheck plus targeted tests passing minimal env literals.
- **Hand-formatted code must match Prettier canon** — **Symptom:** `prettier --check` fails on hand-written files when the author cannot run Prettier. **Root cause:** breakable calls/objects written past the print width inline (including single long string args, which Prettier still splits onto their own line with a trailing comma), or expanded constructs that would join within one line. **Prevention/handling:** expand multi-arg calls/objects one-per-line with trailing commas once the joined form exceeds the width (single-arg calls included), collapse short blocks that fit, keep unbreakable string/template literals and last-arg function hugs as-is, prefer restructuring (e.g. namespace import + property access) so every line is short and unambiguous instead of guessing a break layout with no repo precedent, and measure every touched line length before handing off. **Verification:** require a length scan of touched files and a reviewer `prettier --check` pass.
- **Portable diff-output paging** — **Symptom:** a review command fails or its output is truncated before producing the requested diff because a pager/filter executable is unavailable or the tool caps output size. **Root cause:** shell environments do not share the same auxiliary command set, and large diffs exceed the transport display limit. **Prevention/handling:** use repository read tools or portable commands for bounded output, inspect the tool-saved full output when available, and do not treat display truncation as a repository failure. **Verification:** rerun/read bounded sections through the supported file/diff tool and confirm the needed paths are covered. **Biến thể:** khi diff toàn repo bị cắt, chuyển ngay sang `--stat`, `--name-status` và diff theo nhóm file liên quan thay vì suy luận từ phần output đã hiển thị. **Biến thể mới:** nếu phần hiển thị vẫn bị cắt nhưng công cụ đã lưu toàn bộ output, đọc source hiện tại theo từng file/hàm và đối chiếu các nhóm diff liên quan; không chạy lại kiểm tra chỉ để thay thế evidence review. **Biến thể checkpoint:** nếu diff nhóm vẫn bị giới hạn hiển thị trong lần review sau repair, dùng file output đã lưu và đối chiếu lại source hiện tại theo symbol/đường dẫn bị ảnh hưởng; chỉ ghi nhận sự cố hiển thị, không biến nó thành evidence kiểm thử. **Biến thể review scope:** khi diff lớn đồng thời chứa baseline của nhiều ticket, đọc bounded diff theo nhóm và đối chiếu với evidence mapping trước khi kết luận scope. **Biến thể round-trip:** nếu diff hiện tại bị cắt trước khi suy ngược, chuyển sang đọc trực tiếp source/test của đúng ticket scope và chỉ dùng PASS evidence đã chỉ định; không mở ticket gốc trước khi hoàn tất phần suy ngược.
- **Verified-path reads** — **Symptom:** a file read fails before review because the supplied path is malformed, including an accidental control character, tab, newline, or null byte. **Root cause:** path separators, escape characters, or control characters were not preserved correctly in the tool argument; Windows backslashes in JSON can turn sequences such as `\t`/`\n` into control characters. **Prevention/handling:** use the verified repository root and exact path, prefer explicit slash separators, and retry only after confirming the target exists; enumerate the parent directory when the exact nested path is uncertain. **Verification:** the subsequent read returns the expected file content before any repository action proceeds. Khi dùng chuỗi đường dẫn Windows trong tham số JSON, ưu tiên dấu `/` để tránh escape như `\r`/`\t` biến thành ký tự điều khiển. **Biến thể:** nếu lệnh đọc đầu tiên dùng candidate path sai hoặc malformed, không tiếp tục đoán; enumerate thư mục cha rồi đọc lại bằng đường dẫn đã xác nhận.
- **Hidden-directory glob discovery** — **Symptom:** a glob search returns no files for a known hidden directory or nested ticket/evidence artifact even though it exists. **Root cause:** the glob tool may omit hidden paths or fail to match them as expected. **Prevention/handling:** verify the repository root and enumerate the immediate parent directory, then read the exact discovered path instead of treating an empty glob result as absence; for a review, enumerate `.scratch` and `.brain/evidence` before resolving the ticket artifacts. **Verification:** the directory listing and exact file read both return the expected artifact. This applies to hidden ticket directories as well: enumerate `.scratch` and its feature parent before concluding the ticket is absent. **Biến thể thực thi:** nếu nhiều candidate glob cho ticket đều rỗng, chỉ enumerate lần lượt `.scratch`, feature parent và `issues/`, không tiếp tục đoán filename.
- **Hidden-path candidate verification** — **Symptom:** a glob or guessed VCS path returns no file while the artifact exists under a different nested issue path, or a referenced document name omits the descriptive suffix used by the repository. **Root cause:** hidden-directory matching and candidate filenames were assumed instead of being resolved from the parent directory first. **Prevention/handling:** enumerate the immediate parent, use the exact discovered path, and only then read or query VCS history; treat a failed candidate lookup as a tooling/path issue, not repository evidence. **Verification:** the exact ticket/evidence/spec path is read successfully before review conclusions are made. **Additional variant:** screen documents may use descriptive filenames rather than the short screen number referenced by a plan, and a feature `spec.md` may live under `.scratch/<feature>/` rather than the repository root; enumerate the parent directory before retrying. When a root-level spec or short screen filename is absent, do not classify it as missing until the feature and UI parent directories have been enumerated and the descriptive filename is read.
  - **Biến thể:** glob có thể trả về rỗng cho thư mục ẩn dù artifact đã tồn tại; chuyển sang enumerate thư mục cha rồi đọc đường dẫn tuyệt đối đã xác nhận, không suy luận là file bị thiếu. Nếu cần tìm nhiều loại artifact, enumerate từng thư mục cha đã xác nhận trước khi đọc, thay vì thử tiếp các candidate path đoán tên.
- **Edit read-back before continuing** — **Symptom:** an edit tool reports success yet silently deletes surrounding logic because the replacement text was truncated (e.g. a multi-line block replaced by its first line only), or a patch reports success without changing the intended text because old and new content are identical. **Root cause:** success only means the old string matched, not that the new string is complete or materially different; the damage or no-op is invisible until runtime/review. **Prevention/handling:** after every edit, read back the touched region and inspect the content diff before the next edit; when applying a reference diff, finish with a byte-level diff against the reference and require zero unexpected lines. **Verification:** the read-back shows the full intended block and confirms the intended content actually changed; the final reference diff is empty of unexpected lines.
- **Diff-scope preflight for evidence** — **Symptom:** an evidence diff lists only modified files while newly created test/migration files are silently missing. **Root cause:** `git diff`/`git diff --stat` cover tracked paths only; untracked files stay invisible until a status probe runs. **Prevention/handling:** pair every evidence diff with `git status --porcelain` scoped to the ticket paths before writing the patch, and list untracked files explicitly. **Verification:** require the patch file list to equal the status file list for the ticket scope.
- **Evidence patch context refresh — additional variant:** **Symptom:** a combined patch is rejected even though the target evidence file was read moments earlier. **Root cause:** the hunk anchored to an older repeated line after the evidence artifact had accumulated later sections. **Prevention/handling:** retry with independent, smaller hunks anchored to unique current lines, then read back every changed region. **Verification:** the final evidence artifact contains the new mapping exactly once and the source changes remain intact.
- **Detail surfaces must bind shared Evidence infrastructure** — **Symptom:** a workflow detail page displays classification and result but cannot upload Evidence or provide persisted download links. **Root cause:** the shared Evidence model/API existed, while the detail surface rendered only raw metadata and never mounted `EvidenceCapture` with the aggregate resource identity. **Prevention/handling:** reuse `EvidenceCapture` with the exact resource type/id, refresh the detail after upload, and render `EvidenceList`; add a persistence/readback regression for the same linkage. **Verification:** assert the stored Evidence has the aggregate `resourceType/resourceId` and the detail query returns it.

- **Explicit-lifecycle fixture linkage** — **Symptom:** a seed or test fails nullable-linkage type errors, or its idempotent second run throws an invalid-transition error after the domain moved child creation to an explicit confirm/convert command. **Root cause:** the fixture was written against the old auto-create flow and treats the linkage as always fresh and non-null instead of branching on the returned linkage. **Prevention/handling:** type the linkage nullable until guarded, reuse the returned linkage when present and otherwise run the verify/convert steps once; keep channel values canonical at the boundary. **Verification:** run the seed twice asserting zero duplicate writes plus typecheck with the optional linkage.

- **Migration-chain allow-list drift** — **Symptom:** a migration-chain assertion fails showing a longer actual chain right after adding migrations, or an additive-SQL check fails on a bare `DROP INDEX`. **Root cause:** the expected chain hardcodes history instead of growing with each migration, and generated drop statements omit `IF EXISTS`. **Prevention/handling:** extend the expected chain in the same change as the migration and author drops with `IF EXISTS`. **Verification:** rerun the migration-contract test plus a no-op migrate status.

- **Test discipline after refactor (Playwright + unit)** — **Symptom:** a refactor passes review yet the full suite/E2E fails late, oversized cases hide the culprit, verbose logs flood CI, web-only tests break for lack of a mobile environment, or one grouped unit case couples unrelated contracts. **Root cause:** Playwright was not rerun after the refactor, one case covered many pages/scenarios, `console.log`/verbose helpers leaked into specs, Web vs Web-App classification was missing so web-only tests implicitly depended on mobile, and unit cases grouped several behaviors instead of one contract each. **Prevention/handling:** rerun Playwright after every refactor; keep each case to one page/tab/business scenario with shared fixtures/helpers and no `console.log`/verbose logging/sleep-retry cover-ups; label Web vs Web-App explicitly, keep Web-App only for genuine mobile interaction and gate it with an existing runtime/config skip flag when mobile is unavailable (never `.env`, never fake-pass); split unit tests per small contract/behavior (canonical/legacy boundary, each valid/invalid transition, each SLA, event catalog, masking/reveal, idempotency) while keeping the no-auto-Incident and exactly-one-Incident-on-convert regressions. **Verification:** full Playwright run green on every project after each refactor, zero `console.log`/verbose matches in specs, web-only suites independent of mobile, and each unit failure points to exactly one contract.

- **CRLF vs Prettier LF canon on Windows** — **Symptom:** `prettier --check` fails only on recently added/edited files while untouched files pass, with no visible spacing or quote difference. **Root cause:** Windows `core.autocrlf` writes CRLF (or mixed endings after partial edits) while the repo Prettier canon is LF, so every CRLF/mixed file is flagged regardless of content. **Prevention/handling:** normalize touched files to LF at byte level before hand-formatting (text-replacement edits preserve surrounding CRLF and create mixed endings, so normalize first with an exact CRLF-to-LF pass); then apply content canon only (trailing commas, join when the joined line fits the width, expand one-per-line when it exceeds it, keep unbreakable strings as-is). **Verification:** scan touched files for zero CR bytes plus a reviewer `prettier --check` pass. **Biến thể tool:** file sửa bằng công cụ edit có thể bị ghi lại toàn bộ sang CRLF dù chỉ đổi vài dòng; phát hiện bằng CR bytes worktree > 0 trong khi `git show HEAD:<file>` CR = 0 và prettier gắn cờ file vốn sạch ở lần chạy trước; sửa bằng một pass CRLF→LF giới hạn đúng file đã chạm, rồi đọc lại diff.
